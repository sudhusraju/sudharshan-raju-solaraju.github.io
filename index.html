1. The Business Problem

Challenge: A global manufacturing company faced frequent stockouts (23% of SKUs), low OTIF (87%), and excess inventory holding costs. Data was siloed across SAP S/4HANA (transactions, inventory, shipments) and SAP BW (historical trends, forecasts). Supply chain planners had no real-time visibility into warehouse performance, supplier reliability, or logistics bottlenecks.

Objective: Build a unified Supply Chain Control Tower using SAP HANA's in-memory computing and SAP BW's aggregated data to provide real-time inventory visibility, predictive shortage alerts, and supplier scorecards.

2. Data Sources – SAP HANA & SAP BW

3. Data Cleaning & Transformation

Before modeling, data from SAP sources required cleaning using Power Query Editor and SAP-specific transformations :

Standardize Material Codes

SAP material numbers (18-digit) vs legacy Excel exports → unified using LEFT function to 8-digit core number.

SAP Date Conversion

SAP internal date format (YYYYMMDD) converted to proper Date type using Date.FromText.

Remove Cancelled Orders

Filtered out delivery documents with status 'C' (Cancelled) and return orders (Movement Type 122, 161).

Unit of Measure Conversion

Standardized quantities from various UoM (PC, CTN, PAL) to base unit 'EA' using SAP conversion factors.

4. Data Modeling – Star Schema Design

Designed a star schema leveraging SAP master data and fact tables :

Fact Tables

Fact_Inventory (MARD): Stock levels, value, quantity per plant/material/date
Fact_Shipments (LIKP/LIPS): Delivery data, quantities, dates
Fact_Purchasing (EKPO/EKKO): PO lines, quantities, delivery dates

Dimension Tables (SAP Master Data)

Dim_Material (MARA): Material number, description, product group, base UoM
Dim_Plant (T001W): Plant code, name, region, storage location type
Dim_Supplier (LFA1): Vendor code, name, payment terms, country
Dim_Date (Auto-generated): Full date hierarchy

Relationship Diagram: Fact tables join to Dim_Material (MATNR), Dim_Plant (WERKS), Dim_Supplier (LIFNR), and Dim_Date (DateKey). All relationships are one-to-many with cross-filter direction set to single.

5. Advanced DAX Measures for Supply Chain

Key business measures created using DAX, optimized for SAP HANA in-memory performance :

📦 Inventory Turnover Ratio

Inventory Turnover =
VAR AvgInventory = AVERAGEX(SUMMARIZE(Fact_Inventory, Dim_Date[YearMonth]), [Ending Inventory Value])
RETURN DIVIDE([Total COGS], AvgInventory)

🚚 OTIF % (On-Time In-Full)

OTIF % =
VAR OnTime = COUNTROWS(FILTER(Fact_Shipments, Fact_Shipments[ActualDeliveryDate] <= Fact_Shipments[RequestedDate]))
VAR InFull = COUNTROWS(FILTER(Fact_Shipments, Fact_Shipments[DeliveryQty] >= Fact_Shipments[OrderQty]))
RETURN DIVIDE(COUNTROWS(INTERSECT(OnTime, InFull)), COUNTROWS(Fact_Shipments))

⚠️ Stockout Rate

Stockout Rate =
VAR StockoutDays = COUNTROWS(FILTER(Fact_Inventory, Fact_Inventory[AvailableStock] = 0 && Fact_Inventory[TotalDemand] > 0))
RETURN DIVIDE(StockoutDays, DISTINCTCOUNT(Dim_Date[Date]))

🏭 Days of Supply (DOS)

Days of Supply =
VAR AvgDailyDemand = AVERAGEX(SUMMARIZE(Fact_Shipments, Dim_Date[Date]), [Total Shipped Qty])
RETURN DIVIDE([Current Inventory Level], AvgDailyDemand)

Additional SAP-integrated measures: Supplier Lead Time Variance, Warehouse Capacity Utilization, Freight Cost per Unit, Forecast Accuracy %.

7. Key Insights Discovered
  • 🏭 Warehouse B Bottleneck: 22% longer dwell time vs. average (from SAP shipment data). AI recommendation: cross-dock re-routing → implemented, reducing logistics spend by 8%.
  • 📦 Slow-Moving SKUs: 14% of inventory (from SAP MARD table) with zero movement in 90+ days. Recommendation: dynamic safety stock recalibration → reduced holding cost by $320k.
  • 🚚 Supplier OTIF Issue: Supplier A at 74% OTIF (from SAP delivery data). Renegotiated terms + backup supplier → improved to 89% within 6 months.
  • 📈 Demand Forecast Accuracy: Seasonal product group had 28% forecast error → implemented SAP IBP integration + ML model → improved to 12% error.
